# Git Ignore Strategy for Platform NBRLY

## Overview
This repository uses a multi-level `.gitignore` strategy to ensure sensitive data, build artifacts, and environment-specific files are never committed.

## Structure

### Root `.gitignore`
Location: `/.gitignore`

**Covers:**
- Azure-specific files (`.azure/`, `*.azureauth`, `azureprofile.json`)
- Infrastructure as Code artifacts (Terraform state, Crossplane configs)
- Environment variables and secrets (`.env*`, `secrets/`, `*.pem`, `*.key`)
- IDE and editor files (VSCode, JetBrains, Vim, Emacs)
- Operating system files (macOS `.DS_Store`, Windows `Thumbs.db`)
- Python artifacts (`__pycache__/`, `*.pyc`, `venv/`)
- Node.js artifacts (`node_modules/`, `npm-debug.log`)
- Docker artifacts
- Build outputs (`dist/`, `build/`, `*.whl`)
- Logs (`*.log`, `logs/`)
- Testing artifacts (`.pytest_cache/`, `.coverage`)
- Deployment artifacts (`scripts/*.output`)

**Explicitly Allowed:**
- Configuration templates (`config/parameters-dev.json` - no secrets)
- Documentation (`docs/`, `README.md`)
- Infrastructure scripts (`scripts/*.sh`)
- Dockerfiles
- CI/CD workflows (`.github/workflows/`)

### Sample App `.gitignore`
Location: `/sample-app/.gitignore`

**Covers:**
- Application-specific Python artifacts
- Local development files
- Docker build contexts
- Environment overrides
- Application logs

## Protected Files (Never Commit)

### 🔴 Critical - Contains Secrets
- `secrets/` directory
- `.env`, `.env.local`, `.env.production`
- `*.pem`, `*.key`, `*.crt`, `*.p12`, `*.pfx`
- `service-account.json`, `credentials.json`
- `*.azureauth`, `azureprofile.json`
- Key Vault exports or secret dumps

### 🟡 Warning - Environment Specific
- `config/*-local.json`
- `config/*-override.json`
- `.azure/` local Azure CLI state
- `local.settings.json` (Azure Functions)
- Terraform state files (`*.tfstate`)

### 🟢 Safe to Commit
- `config/parameters-dev.json` (template, no secrets)
- `README.md`, documentation
- Infrastructure scripts (`scripts/*.sh`)
- Application code (`main.py`, `Dockerfile`)
- CI/CD workflows

## Testing Gitignore Rules

Test if a file will be ignored:
```bash
git check-ignore -v filename.ext
```

Test multiple files:
```bash
printf "file1\nfile2\nfile3" | git check-ignore --stdin -v
```

Check what would be ignored in current directory:
```bash
git status --ignored
```

## Common Patterns

### Azure Infrastructure
```
.azure/                    # Azure CLI local state
*.azureauth               # Azure authentication files
azureprofile.json         # Azure profile settings
config/*-local.json       # Local config overrides
scripts/*.output          # Script execution logs
```

### Development
```
__pycache__/              # Python bytecode cache
*.pyc, *.pyo             # Python compiled files
node_modules/            # Node.js dependencies
venv/, .venv/            # Python virtual environments
.env*                    # Environment variables
```

### Build & Deploy
```
dist/, build/            # Build outputs
*.whl, *.egg            # Python packages
docker-compose.override.yml  # Local Docker overrides
deployment-logs/         # Deployment artifacts
```

## Migration Notes

When adding new applications (frontend, backend):
1. Each app should have its own `.gitignore`
2. Root `.gitignore` handles common patterns
3. App-specific `.gitignore` handles app artifacts

Example structure:
```
platform-nbrly/
├── .gitignore              # Root (infrastructure, common)
├── sample-app/
│   └── .gitignore         # Python/FastAPI specific
├── frontend/              # Future
│   └── .gitignore         # React/Node.js specific
└── backend/               # Future
    └── .gitignore         # Python/FastAPI specific
```

## Best Practices

1. **Never commit secrets**: Use Azure Key Vault, environment variables, or secure CI/CD secrets
2. **Use templates**: Provide `.env.example`, `config.template.json` for team onboarding
3. **Review before commit**: Always check `git status` before committing
4. **Test locally**: Use `.env.local` for local overrides (already ignored)
5. **Document exceptions**: If you need to commit an unusual file, document why

## Emergency: Removing Committed Secrets

If secrets were accidentally committed:

```bash
# Remove from current commit
git rm --cached <file>
git commit --amend

# Remove from history (DANGER - rewrites history)
git filter-branch --force --index-filter \
  "git rm --cached --ignore-unmatch <file>" \
  --prune-empty --tag-name-filter cat -- --all

# Force push (only if no one else has pulled)
git push origin --force --all
```

**Then**: Rotate all exposed secrets immediately in Azure Key Vault!
