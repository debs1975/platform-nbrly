# Container App YAML Manifests

This directory contains YAML manifest templates and generated configurations for deploying the sample API to Azure Container Apps.

## Directory Structure

```
manifests/
├── containerapp.yaml           # Template with {{variable}} placeholders
├── .generated/                 # Auto-generated manifests (gitignored)
│   ├── containerapp-dev.yaml
│   ├── containerapp-staging.yaml
│   └── containerapp-prod.yaml
├── .gitignore                  # Excludes generated files
└── README.md                   # This file
```

## Files

### `containerapp.yaml` (Template)

The master template containing all Container App configuration with variable placeholders.

**Variables to Replace:**
- `{{APP_NAME}}` - Container App name
- `{{CAE_NAME}}` - Container Apps Environment name
- `{{IMAGE_NAME}}` - Full container image path with tag
- `{{UAMI_ID}}` - User-assigned managed identity resource ID
- `{{UAMI_CLIENT_ID}}` - Managed identity client ID
- `{{ACR_SERVER}}` - Azure Container Registry URL
- `{{ENVIRONMENT}}` - Environment name (dev/staging/prod)
- `{{PROJECT_NAME}}` - Project name
- `{{KV_NAME}}` - Key Vault name
- `{{MAX_REPLICAS}}` - Maximum replica count
- `{{SUBSCRIPTION_ID}}` - Azure subscription ID
- `{{RESOURCE_GROUP}}` - Resource group name
- `{{CREATED_DATE}}` - Deployment date

### `.generated/` Directory

Contains environment-specific manifests generated by `deploy-yaml.sh` with all variables substituted.

**These files are:**
- ✅ Auto-generated during deployment
- ✅ Environment-specific (dev, staging, prod)
- ✅ Excluded from Git (see `.gitignore`)
- ✅ Used by Azure CLI for actual deployment

## Usage

### Deploy Using YAML

```bash
# From sample-app directory
./scripts/deploy-yaml.sh dev
```

This script:
1. Loads configuration from `config/parameters-{env}.json`
2. Builds and pushes Docker image to ACR
3. Generates manifest from template (variable substitution)
4. Saves to `.generated/containerapp-{env}.yaml`
5. Deploys using `az containerapp create --yaml` or `az containerapp update --yaml`

### Manual Variable Substitution

If you need to generate the manifest manually:

```bash
# Set variables
APP_NAME="nbrly-dev-eastus-api-ca"
CAE_NAME="nbrly-dev-eastus-cae"
IMAGE_NAME="nbrlydeveastusacr.azurecr.io/sample-api:latest"
# ... set all other variables

# Perform substitution
sed -e "s|{{APP_NAME}}|${APP_NAME}|g" \
    -e "s|{{CAE_NAME}}|${CAE_NAME}|g" \
    -e "s|{{IMAGE_NAME}}|${IMAGE_NAME}|g" \
    # ... add all other substitutions
    containerapp.yaml > .generated/containerapp-dev.yaml

# Deploy
az containerapp create \
  --resource-group nbrly-dev-eastus-rg \
  --name nbrly-dev-eastus-api-ca \
  --yaml .generated/containerapp-dev.yaml
```

### View Deployed Configuration

```bash
# Export current Container App as YAML
az containerapp show \
  --name nbrly-dev-eastus-api-ca \
  --resource-group nbrly-dev-eastus-rg \
  --output yaml > deployed-config.yaml
```

## YAML Structure

### Top-Level Sections

```yaml
properties:
  environmentId: ...          # Container Apps Environment reference
  configuration:              # App configuration
    ingress: ...             # Ingress/routing rules
    registries: ...          # Container registry settings
    secrets: ...             # Secret definitions
  template:                  # Container template
    containers: ...          # Container specs
    scale: ...              # Scaling rules

identity:                    # Managed identity
  type: UserAssigned
  userAssignedIdentities: ...

tags: ...                    # Resource tags
```

### Key Configuration Sections

#### 1. Ingress Configuration

```yaml
configuration:
  ingress:
    external: true           # Publicly accessible
    targetPort: 8000        # Container port
    transport: auto         # HTTP/HTTP2
    allowInsecure: false    # HTTPS only
    traffic:
      - latestRevision: true
        weight: 100
```

#### 2. Registry Authentication

```yaml
configuration:
  registries:
    - server: nbrlydeveastusacr.azurecr.io
      identity: /subscriptions/.../userAssignedIdentities/...
```

Uses managed identity instead of admin credentials.

#### 3. Secrets from Key Vault

```yaml
configuration:
  secrets:
    - name: postgres-connection-string
      keyVaultUrl: https://nbrlydeveastuskv.vault.azure.net/secrets/postgres-connection-string
      identity: /subscriptions/.../userAssignedIdentities/...
```

Secrets are pulled from Key Vault using managed identity.

#### 4. Container Configuration

```yaml
template:
  containers:
    - name: api
      image: nbrlydeveastusacr.azurecr.io/sample-api:latest
      resources:
        cpu: 0.5
        memory: 1.0Gi
      env:
        - name: ENVIRONMENT
          value: "dev"
        - name: DATABASE_URL
          secretRef: postgres-connection-string
```

#### 5. Health Probes

```yaml
template:
  containers:
    - probes:
        - type: liveness
          httpGet:
            path: /app1/health/live
            port: 8000
          failureThreshold: 3
        - type: readiness
          httpGet:
            path: /app1/health/ready
            port: 8000
          failureThreshold: 3
```

#### 6. Scaling Rules

```yaml
template:
  scale:
    minReplicas: 0
    maxReplicas: 10
    rules:
      - name: http-rule
        http:
          metadata:
            concurrentRequests: "10"
```

## Benefits of YAML Deployment

### Version Control
- Track configuration changes in Git
- Review changes in pull requests
- Rollback to previous versions easily

### Declarative Configuration
- Define desired state, not imperative steps
- Easier to understand complete configuration
- Self-documenting infrastructure

### GitOps Integration
- Can be used with ArgoCD, Flux, or other GitOps tools
- Automated deployments via Git commits
- Drift detection and reconciliation

### Environment Parity
- Same template for all environments
- Only variables differ between dev/staging/prod
- Reduces configuration drift

### Easier Troubleshooting
- Full configuration visible in one file
- Compare generated manifests between environments
- Export deployed config for debugging

## Modifying the Template

### Add Environment Variable

```yaml
template:
  containers:
    - env:
        # Add new variable
        - name: NEW_VARIABLE
          value: "{{NEW_VALUE}}"
```

Then update `deploy-yaml.sh` to substitute `{{NEW_VALUE}}`.

### Change Resource Limits

```yaml
template:
  containers:
    - resources:
        cpu: 1.0          # Changed from 0.5
        memory: 2.0Gi     # Changed from 1.0Gi
```

### Add Scaling Rule

```yaml
template:
  scale:
    rules:
      - name: http-rule
        http:
          metadata:
            concurrentRequests: "10"
      # Add CPU-based scaling
      - name: cpu-rule
        custom:
          type: cpu
          metadata:
            type: Utilization
            value: "70"
```

### Enable CORS

Uncomment the CORS section in the template:

```yaml
configuration:
  ingress:
    corsPolicy:
      allowedOrigins:
        - "https://*.azurecontainerapps.io"
      allowedMethods:
        - GET
        - POST
        - PUT
        - DELETE
      allowedHeaders:
        - "*"
```

## Validation

### Syntax Validation

```bash
# Check YAML syntax (requires yq or similar)
yq eval .generated/containerapp-dev.yaml

# Or use Python
python -c "import yaml; yaml.safe_load(open('.generated/containerapp-dev.yaml'))"
```

### Dry Run

```bash
# Azure CLI doesn't support dry-run, but you can validate by:
# 1. Generate the manifest
./scripts/deploy-yaml.sh dev

# 2. Review the generated file
cat .generated/containerapp-dev.yaml

# 3. Compare with current deployment
az containerapp show \
  --name nbrly-dev-eastus-api-ca \
  --resource-group nbrly-dev-eastus-rg \
  --output yaml > current.yaml

diff current.yaml .generated/containerapp-dev.yaml
```

## Troubleshooting

### Variable Not Substituted

If you see `{{VARIABLE}}` in the generated manifest:
1. Check the variable is defined in `deploy-yaml.sh`
2. Verify the sed substitution includes this variable
3. Check for typos in variable names

### Deployment Fails

```bash
# Check the generated manifest
cat .generated/containerapp-dev.yaml

# Validate resource references exist
az containerapp env show --name $CAE_NAME --resource-group $RG_NAME
az identity show --name $UAMI_NAME --resource-group $RG_NAME
```

### Secret Access Issues

```bash
# Verify Key Vault exists and secrets are present
az keyvault secret list --vault-name $KV_NAME

# Check managed identity has Key Vault permissions
az role assignment list --assignee $UAMI_PRINCIPAL_ID --scope $KV_ID
```

## Best Practices

1. **Always use the template** - Don't manually edit generated files
2. **Review generated manifests** - Check `.generated/` files before deployment
3. **Test in dev first** - Validate changes in dev before prod
4. **Version control the template** - Commit `containerapp.yaml` to Git
5. **Document custom changes** - Add comments for non-obvious configurations
6. **Use consistent naming** - Follow the project naming conventions
7. **Keep secrets in Key Vault** - Never hardcode secrets in YAML
