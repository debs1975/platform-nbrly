# Configuration Directory

This directory contains environment parameters and infrastructure state for `app-gtway-apps` deployment.

## Files

### `parameters-dev.json`

Environment-specific parameters including:
- Azure region and environment
- Virtual network configuration
- Domain names and SSL certificates
- Tenant domain mappings

**Note**: Copied from `iac-cli/config/parameters-dev.json`

### `.generated/generated-infra-dev.json`

Infrastructure state file generated by IaC deployment. Contains:
- Resource Group name
- Container Registry details
- Container App Environment names
- Application Gateway configuration
- Managed Identity IDs

## Setup Instructions

### Option 1: Copy from IaC Deployment

If you have `iac-cli` deployed:

```bash
mkdir -p .generated
cp ../../iac-cli/config/.generated/generated-infra-dev.json ./.generated/
```

### Option 2: Copy from Team Member

Get the state file from your team:

```bash
# Place the file provided by your team into:
.generated/generated-infra-dev.json
```

### Option 3: Manual Setup

If you have the infrastructure deployed but no state file, create the file manually:

```json
{
  "common": {
    "resourceGroupName": "nbrly-dev-eastus-rg",
    "appGatewayName": "nbrly-dev-eastus-agw",
    "containerRegistryName": "nbrlydeveastusacr",
    "containerRegistryUrl": "nbrlydeveastusacr.azurecr.io"
  },
  "tenants": {
    "nbrly": {
      "containerAppEnvironmentName": "nbrly-dev-eastus-cae",
      "containerAppEnvironmentId": "/subscriptions/{sub}/resourceGroups/{rg}/providers/Microsoft.App/managedEnvironments/nbrly-dev-eastus-cae",
      "userAssignedManagedIdentityId": "/subscriptions/{sub}/resourceGroups/{rg}/providers/Microsoft.ManagedIdentity/userAssignedIdentities/nbrly-uami"
    },
    "bloom": {
      "containerAppEnvironmentName": "bloom-dev-eastus-cae",
      "containerAppEnvironmentId": "/subscriptions/{sub}/resourceGroups/{rg}/providers/Microsoft.App/managedEnvironments/bloom-dev-eastus-cae",
      "userAssignedManagedIdentityId": "/subscriptions/{sub}/resourceGroups/{rg}/providers/Microsoft.ManagedIdentity/userAssignedIdentities/bloom-uami"
    }
  }
}
```

Replace placeholders with your actual resource details.

## Multi-Environment Support

For production deployments, create separate parameter files:

```
config/
├── parameters-dev.json
├── parameters-staging.json
├── parameters-prod.json
└── .generated/
    ├── generated-infra-dev.json
    ├── generated-infra-staging.json
    └── generated-infra-prod.json
```

## Finding Infrastructure Details

### Get Resource Group Name

```bash
az group list --query "[].name" -o table
```

### Get Container Registry Details

```bash
az acr list --query "[].{name:name, resourceGroup:resourceGroup}" -o table
```

### Get Container App Environment

```bash
az containerapp env list --query "[].{name:name, id:id, resourceGroup:resourceGroup}" -o table
```

### Get Application Gateway

```bash
az network application-gateway list --query "[].{name:name, id:id, resourceGroup:resourceGroup}" -o table
```

### Get Managed Identity

```bash
az identity list --query "[].{name:name, id:id, resourceGroup:resourceGroup}" -o table
```

## Important Notes

- ⚠️ **DO NOT commit** `.generated/generated-infra-dev.json` to version control (contains sensitive IDs)
- The `.gitignore` file at the root excludes these automatically
- Each environment should have its own state file
- Keep backups of state files for disaster recovery
- State files should be managed like infrastructure credentials

---

**For isolated app-gtway-apps deployment**, ensure `.generated/generated-infra-dev.json` exists before running deployment scripts.
