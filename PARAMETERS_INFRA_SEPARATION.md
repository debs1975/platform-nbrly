# Parameters vs Infrastructure File Separation

## Principle
- **parameters-{env}.json**: Contains INPUT parameters needed to CREATE resources
- **infra-{env}.json**: Contains GENERATED properties AFTER resources are created

## Generated Properties (Removed from Parameters, Kept in Infra)

### From Container App Environment
- `defaultDomain` - Generated by Azure after CAE creation (e.g., `grayfield-aa4022a1.eastus.azurecontainerapps.io`)
- `staticIP` - Assigned to CAE by Azure after creation (e.g., `10.100.10.122`)

### Derived from Generated Properties
- `privateDnsZone.name` - Generated from CAE defaultDomain
- `httpRouting.fqdn` - Constructed from CAE name + defaultDomain
- `applicationGateway.backendPool.fqdn` - Constructed from CAE FQDNs
- `applications[].fqdn` - Constructed from app name + CAE defaultDomain

## Input Parameters (Kept in Parameters Files)

### Container App Environment
```json
{
  "name": "nbrly-dev-cae",          // Resource name
  "subnet": "snet-nbrly-dev-cae",   // Subnet to deploy in
  "subnetPrefix": "10.100.10.0/24", // Subnet CIDR
  "internal": true                  // Ingress configuration
}
```

### Private DNS Zone
```json
{
  "vnetLinkName": "astra-dev-eastus-vnet-link"  // Link resource name
}
```

### HTTP Routing
```json
{
  "routeConfigName": "nbrly-dev-cae"  // Route configuration name
}
```

### Application Gateway Backend Pool
```json
{
  "name": "nbrly-bp"  // Pool resource name
}
```

### Applications
```json
{
  "name": "ca-nbrly-nbapp1-dev",
  "image": "astradeveastusacr.azurecr.io/nbrly-nbapp1",
  "rootPath": "/app1",
  "targetPort": 8000
}
```

## Example Workflow

1. **Script reads parameters-dev.json**: Gets `name: "nbrly-dev-cae"`, `subnet: "snet-nbrly-dev-cae"`, etc.

2. **Script creates CAE**: Azure generates `defaultDomain: "grayfield-aa4022a1.eastus.azurecontainerapps.io"`

3. **Script updates infra-dev.json**: Stores the generated defaultDomain and static IP

4. **Subsequent operations**: Use infra-dev.json to get FQDNs and generated properties for routing, backend pool configuration, etc.
